## 3. 시안과 실제 데이터가 다른 곳

| 시안 | 실제 | 처리 |
|---|---|---|
| 기간 끝 `until`과 마감 `due`가 따로 있음 | `due_date_key` 하나를 캘린더 기간 막대의 끝으로 씀 (`spanEvents.ts`) | 지금 의미를 유지하고 한 필드로 합친다. 마감 탭은 `due_date_key` 기준 |

| 상태 `todo / doing / done` | `not-start / in-progress / done` | 매퍼에서 변환 |

| 시안의 샘플 데이터와 규칙 기반 AI | 없음 | 옮기지 않는다 |

## 4. 공통 작업과 주의점

- **시안 코드는 그대로 옮기지 않는다.** 전역 스크립트와 문자열 HTML이고, 고르지 않은 시안 분기가 많다. 확정한 분기의 구조와 CSS 값만 React 컴포넌트로 다시 쓴다.
- **토큰:** 색은 `app/styles/tokens/colors.css`와 이미 같다. 새 값은 토큰으로 추가한다.
- **다국어:** 문구는 전부 i18n 키로 만든다. 지금 16개 언어이고 시안은 한국어뿐이다.
- **데모 모드:** `?demo=true`에서 실제 API를 호출하지 않는 동작을 새 화면도 지켜야 한다.
- **Rough.js:** 런타임 라이브러리 추가 금지 규칙에 걸린다. 빌드 시 빗금 프레임을 미리 SVG로 만들어 넣는 방식을 제안한다. 빌드 전용 의존성은 허용된다.
- **상태 저장소:** `AppProvider.tsx`가 2,095줄이다. 새 기능은 여기에 더 넣지 않고 위젯 단위 훅으로 분리한다.
- **접근성:** 시안에서 맞춘 키보드 동작(Esc, 화살표, 포커스 복귀)을 함께 옮긴다.
- **다국어 빌드:** 키가 하나라도 빠지면 컴파일이 멈춘다. 작업 중에는 미번역 언어에 영어 값을 넣는다.
- **검증:** 단계마다 `pnpm build`와 실제 화면 확인.

## 5. 정해야 할 것

1. 파비콘. 파일 하나를 앱과 랜딩이 같이 쓴다. 제안: 앱 작업 때 39번으로 바꾸되, 랜딩을 안 건드리려면 지금 것을 유지한다.
2. 사용자 캘린더(개인, 팀, 스터디)를 실제로 만들지, 태그로만 갈지
3. 처음 열 화면 기본값. AI가 준비되기 전에는 캘린더를 제안한다.
4. AI 없이 1차 출시할지. 제안: 1~5단계를 먼저 내고 AI 진입점은 숨긴다.
5. 번역 방식. 제안: 작업 중에는 나머지 14개 언어에 영어 값을 넣어 빌드를 유지하고, 출시 전에 일괄 번역한다.
6. 모바일 범위. 시안은 375px 넘침만 확인했고 모바일 전용 화면은 설계하지 않았다.
